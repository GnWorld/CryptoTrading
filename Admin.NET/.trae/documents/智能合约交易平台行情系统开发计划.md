# 智能合约交易平台行情系统开发计划

## 一、K线数据模块

### 1. 设计K线数据模型
- 创建`Candlestick`实体类，包含以下字段：
  - Symbol：交易对标识
  - Interval：K线周期（如1min, 5min, 1h, 1d）
  - OpenTime：开盘时间
  - Open：开盘价
  - High：最高价
  - Low：最低价
  - Close：收盘价
  - Volume：成交量
  - CloseTime：收盘时间
  - QuoteAssetVolume：计价资产成交量
  - NumberOfTrades：成交笔数
  - TakerBuyBaseAssetVolume：主动买入基础资产成交量
  - TakerBuyQuoteAssetVolume：主动买入计价资产成交量

### 2. 实现K线数据收集
- 扩展`BinanceMarketSourceService`，添加K线数据订阅
- 支持多种K线周期（1min, 5min, 15min, 1h, 4h, 1d）
- 实现K线数据的实时更新逻辑

### 3. 实现K线数据存储服务
- 创建`CandlestickService`，负责K线数据的存储和管理
- 实现K线数据的增量更新和历史数据补全
- 优化存储策略，根据K线周期调整存储频率

## 二、REST API接口模块

### 1. 实现行情查询接口
- 创建`MarketController`，提供以下接口：
  - GET /api/market/instruments：获取所有交易品种
  - GET /api/market/ticker/{symbol}：获取单个交易对最新行情
  - GET /api/market/tickers：获取所有交易对最新行情
  - GET /api/market/candlestick/{symbol}/{interval}：获取K线数据

### 2. 实现数据过滤和分页
- 支持按时间范围查询K线数据
- 支持分页查询历史K线数据
- 实现数据缓存，提高查询性能

## 三、WebSocket服务模块

### 1. 实现WebSocket服务
- 创建`MarketWebSocketHandler`，处理前端WebSocket连接
- 支持多种消息类型：
  - 订阅/取消订阅行情
  - 订阅/取消订阅K线数据
  - 心跳检测

### 2. 实现行情推送机制
- 实时推送最新行情数据到订阅的客户端
- 实现推送频率控制，避免过度推送
- 支持按交易对筛选推送数据

### 3. 实现K线推送机制
- 推送实时更新的K线数据
- 支持不同周期的K线推送

## 四、系统集成与优化

### 1. 集成现有行情服务
- 将WebSocket服务与`MarketSnapshotService`集成
- 实现行情数据的统一管理和分发

### 2. 性能优化
- 优化内存使用，减少不必要的对象创建
- 实现异步处理，提高系统吞吐量
- 优化数据库查询，提高数据读写性能

### 3. 监控与日志
- 添加行情系统监控指标
- 实现详细的日志记录，便于问题排查

## 五、开发顺序

1. 设计和实现K线数据模型
2. 扩展`BinanceMarketSourceService`，添加K线数据订阅
3. 实现`CandlestickService`，负责K线数据存储
4. 实现REST API接口
5. 实现WebSocket服务
6. 进行系统集成和测试
7. 性能优化和监控

## 六、技术要点

- 使用Binance.Net库获取行情数据
- 使用SqlSugar进行数据库操作
- 使用ASP.NET Core WebSocket支持实时推送
- 实现高效的内存缓存机制
- 考虑系统的可扩展性和性能

该计划将帮助我们构建一个完整的行情系统，支持K线数据存储、REST API查询和WebSocket实时推送，为前端提供流畅的行情展示体验。
